## Stack
- TypeScript, pnpm (package in `./`)
- Cloudflare Workers (Wrangler 4) with one SQLite-backed Durable Object
- Vitest 5 with `@cloudflare/vitest-plugin`: tests run inside workerd

## Project structure

- `src/index.ts`: the Worker's fetch handler and routes
- `src/hub.ts`: the `Hub` Durable Object (state, later WebSockets)
- `test/`: Vitest tests run in the Workers runtime
- `wrangler.jsonc`: Worker name, bindings, Durable Object exports
- `worker-configuration.d.ts`: generated by `pnpm types`; never edit by hand

## Architecture rules

- All state lives in the one `Hub` Durable Object (`getByName("main")`).
- Cloudflare Workers Builds deploys `main`. GitHub Actions only checks.
- After changing `wrangler.jsonc`, run `pnpm types` and commit the result
  (CI fails otherwise).
- Durable Object classes are declared in `exports` in `wrangler.jsonc`, not
  the legacy `migrations` array. A new, renamed or deleted class needs
  `wrangler deploy` (the `main` build); a branch build cannot apply it.

## Build & dev commands

```sh
pnpm install
pnpm dev                         # local Worker on http://localhost:8787
pnpm typecheck && pnpm lint && pnpm test
python3 .claude/suite-check.py   # every health check in .claude/suite.json
```

## Task tracking
Work is tracked in GitHub Issues. Every issue carries a `type:`, an `area:` and
a priority (`p0`-`p3`) label. Close issues from the pull request with
`Fixes #N`.

## Commits & pull requests

- One pull request per piece of work, never one per tweak. Its `## Changelog`
  section gives each change a line (`- feature: ...`, `- fix: ...`,
  `- chore: ...`). Split only for risk, an independent revert or a different
  release.
- Changelog lines and titles are public release-notes copy: imperative,
  sentence case, no trailing period, no em dashes.
- Every pull request needs an `area:` label, plus a `type:` label when it has
  no Changelog section, before it can merge (the `pr-labelled` status). Which
  type: see `.github/pull_request_template.md`.
